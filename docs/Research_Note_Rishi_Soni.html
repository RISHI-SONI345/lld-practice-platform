The gap

The LLD practice pages we could read score a learner's answer against a reference solution or a rubric. None of them says which feedback is produced by a repeatable rule and which is a model's opinion. That is the gap this platform is built on.

How a learner practises

Hello Interview's preparation guide splits an LLD answer into five timed phases: requirements, entities and relationships, class design, implementation, and verification by tracing a scenario. It says pseudocode is usually acceptable and lists over-engineering and unrequested methods among common mistakes (guide). This supports two choices here: a staged attempt, and a one-line rationale for the pattern used and the pattern rejected.

Gaps we use

  1. Fact versus judgment. No page we read labels which findings come from rules and which from a model. Every finding here carries FACT or JUDGMENT, and the report puts facts first.
  2. No single reference answer. AlgoMaster states it grades against a reference solution. We grade against decision points with several accepted approaches, so a different valid design is not marked wrong.
  3. Cost of change to the learner's own design. None of the pages we read describes measuring how much of the learner's own design breaks under a new requirement. We report this as blast radius.
  4. No execution. AlgoMaster and LowLevelDesign Mastery run code. We parse structure only and say so, which removes the sandbox but also means behaviour is never tested.

Evidence behind the design

  • Why the split. One recent study finds that a model judging unchanged code can change its verdict with prompt cues and across repeated runs, and recommends neutral templates and checks that can be run (arXiv 2604.16790). Another finds a judge can be very consistent across runs without being valid (arXiv 2606.19544). So anything countable stays out of the model, the prompt is neutral, temperature is 0, and the AI output is labelled advisory. Consistency would not prove it right.
  • Why the God Class rule is limited. The published detection strategy combines access to foreign data, weighted method count and class cohesion (Marinescu, detection strategies). The latter two need body-level analysis we do not do, so GOD_CLASS counts members only and says so.
  • Why parse failures are per file. JavaParser recovers at statement level and at file level, and a file it cannot recover keeps little beyond the token range (JavaParser docs). So a partial model is per file, not per declaration.

What this research does not show

It shows what the vendors say on their pages, not how good their feedback is. We did not test the tools ourselves, and we did not validate our own AI review against a panel of human reviewers. Those are the weakest points of the evidence.
